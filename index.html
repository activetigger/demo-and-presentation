De quoi on parle ?

ActiveTigger : un logiciel libre pour mettre des étiquettes sur du texte à grande échelle.

Concrètement

  • J’ai 50 000 résumés d’articles, je veux savoir lesquels parlent d’un sujet donné
  • Annoter tout à la main = trop long ; un script seul = peu collaboratif et peu contrôlé

La solution : une application web qui combine

  • annotation humaine assistée (active learning)
  • entraînement de classifieurs (de modèles légers à des BERT)
  • prédiction sur tout le corpus

Et d’autres features pour faciliter l’exploration et l’interaction des données en gardant l’humain dans la boucle.

Pourquoi ça existe ?

  • Né d’un besoin de recherche en sciences sociales computationnelles
    • Groupe CSS@IPP au CREST (Étienne Ollion & co.)
  • Objectif : démocratiser une chaîne de traitement NLP au-delà des gens qui codent
    • Idée originale de Julien Boelaert
  • Une communauté d’utilisateurs qui grandit, et donc des besoins logiciels réels

Aujourd’hui : une V1 en production, des utilisateurs actifs, et le double mouvement

  • de consolider
  • d’ajouter des features

Utilisé dans la recherche

  • Le prix de la visibilité. Une analyse computationnelle des interactions en ligne avec des député·es français·es. Revue française de science politique, Claesson A., 2025
  • La part du genre. Genre et approche intersectionnelle dans les sciences sociales françaises au XXIe siècle, Boelaert J. et al, 2025.

Nos valeurs (qui guident le code)

  • Augmenter l’humain, pas le remplacer : l’humain garde le contrôle
  • Code auditable : maîtriser les composants utilisés
  • Open source & collaboratif : contributions, comité scientifique, retours utilisateurs
  • Évolutif : l’outil suit les besoins réels

Concrètement : on privilégie la transparence et la simplicité aux boîtes noires.

La boucle centrale

  1. L’utilisateur annote quelques exemples
  2. Il entraîne un premier classifieur
  3. Le modèle prédit et permet de se concentrer sur des cas (incertains ou probables)
  4. On annote en priorité ces cas → on réentraîne → on itère
  5. On entraine un modèle plus lourd

La partie ML

Deux familles de modèles :

Modèles “quick” Modèles BERT
Paramètres centaines centaines de millions
Pré-entraînement aucun gros corpus
Temps d’entraînement quelques secondes dizaines de min (GPU utile)
  • Embeddings : transformer un texte en vecteur qui capture le sens
  • Classifieur : à partir du vecteur, prédire une étiquette
  • Évaluation : mesurer la qualité sur des données mises de côté (train / test)

Tout ça est déjà implémenté — on ne réinvente pas les méthodes

Architecture technique

  • Frontend : application web (React / TypeScript)
  • Backend : API Python (FastAPI)
  • ML : PyTorch / HuggingFace transformers, scikit-learn
  • Données : base de données (postgreSQL ou SQLite) + fichiers de projet
  • Calcul : jobs d’entraînement (CPU / GPU selon l’instance)

Déploiement possible avec un docker compose
